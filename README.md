# Signal-Foundry

Продакшен-сервис: дашборд, Top signals `editorial-v3`, JSON/RSS API, отдельный сборщик и опциональная публикация в Telegram. Сбор включает Reddit, новостные и авторские RSS/Atom-ленты, блоги лабораторий, GitHub Trending, модели и статьи Hugging Face. Хабр исключён. Ключи Reddit не нужны. Python 3.11+, Linux; веб обслуживает Gunicorn.

Запуск и эксплуатация: **[DEPLOYMENT.md](DEPLOYMENT.md)**. В Docker по умолчанию работают `worker` и `web`; Telegram включается профилем `telegram`. Данные хранятся в постоянном Docker volume. Команды `bot.py` и `server.py` ниже предназначены для отдельных локальных запусков; не запускайте их параллельно со сборщиком Docker на одной базе.

```sh
python3 ops.py init-env
docker compose up -d --build --wait worker web
```

Дашборд: http://127.0.0.1:8765. Для переноса существующей истории сначала выполните импорт из инструкции по эксплуатации.

Упаковка для сервера: `make check`, `make build`, `make up`. Есть CI для GitHub Actions и отдельный [Compose для HTTPS](compose.https.yaml) через Caddy. Настройка домена, резервные копии, обновление и восстановление описаны в [DEPLOYMENT.md](DEPLOYMENT.md).

Top signals поддерживает отдельные рейтинги моделей, GitHub, научных статей и изданий, а также сортировку по метрике источника там, где она доступна. [Правила ранжирования и сравнение с референсом](SIGNAL_RANKING.md).

Фоновый сбор обновляет по одному источнику по сохранённому расписанию, с паузами на домен и растущим backoff после 429. [Настройки и поведение ручного обновления](COLLECTION.md).

Добавлены [12 облачных AI-лент](CLOUD_NEWS.md). Доступность модели у провайдера прикрепляется к релизу строкой «Где взять»; отдельные облачные события доступны в категории «Облака».

[Replicate Hype](https://hype.replicate.dev/) подключён через публичный JSON API. Репозитории и модели попадают в свои колонки, совпадения с прямыми источниками объединяются. [Метрики, даты и фильтры Hype](REPLICATE_HYPE.md).

Публикация содержит рубрику, жирный заголовок, фрагмент исходного текста до 900 символов, ссылки на первоисточник и обсуждение. HTML, служебная подпись Reddit и превью картинок удаляются. Ссылки Hugging Face и GitHub показываются первыми. Если текста нет, бот публикует заголовок и ссылки. Автоматического перевода и генерации пересказа нет: фрагмент остаётся на исходном языке, без придуманных подробностей.

Предпросмотр ленты: `news-preview.html`. Обновить его реальными записями RSS без отправки в Telegram: `python3 scripts/preview.py`. Если часть лент недоступна, на странице появится пометка. Если все недоступны или подходящих постов нет, предыдущий файл сохраняется.

## Запуск

1. Создайте бота через @BotFather и добавьте его администратором канала с правом публикации.
2. Создайте локальный файл настроек:

   ```sh
   cp .env.example .env
   chmod 600 .env
   ```

3. Заполните `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Для публичного канала подойдёт `@channel`, для закрытого — числовой ID вида `-100…`. Переменные окружения имеют приоритет над `.env`.
4. Проверьте чтение и отбор без публикаций:

   ```sh
   python3 bot.py --dry-run --once
   ```

5. Запустите бот:

   ```sh
   python3 bot.py
   ```

Для одного прохода с отправкой: `python3 bot.py --once`. Остановка: Ctrl+C. История хранится в `data/state.sqlite3` и сохраняется между запусками. Один файл базы обслуживается только одним процессом публикации.

В Docker публикация включается отдельно после настройки токена:

```sh
docker compose --profile telegram up -d --build worker web publisher
docker compose logs -f publisher
```

В этой конфигурации данные сохраняются в volume `reddit-reposter_signal-data` после пересоздания контейнеров; локальный каталог `data` импортируется отдельно.

## Что фильтруется

В `config.json` указаны сабреддиты, группы RSS, ключевые слова и интервалы:

- Будни: `top/.rss?t=day`, возраст до 24 часов. Выходные: `top/.rss?t=week`, затем отсечение старше 48 часов. Часовой пояс — `Europe/Berlin`.
- Заголовок должен содержать разрешённое слово и не содержать ни одного исключения. Регистр не учитывается. Названия Qwen3 и GPT-5 подходят; API внутри capital не совпадает.
- MachineLearning требует `[R]`, `[N]` или `[P]` в заголовке; `[D]` отбрасывается.
- ClaudeAI, singularity, DeepSeek и Qwen_AI требуют название модели или release/launch/announces/released.
- Драма по словам drama/controversy/scandal/lawsuit/fired разрешена только из LocalLLaMA и singularity.
- Приоритеты: релиз весов с benchmark/числами, локальный запуск с цифрами, агентные/локальные инструменты с GitHub, исследования, остальные новости. Классификация основана на эвристиках.

**Ограничения RSS:** рейтинг и флер поста отсутствуют. Пороги 30/100/300 и проверка флеров LocalLLaMA не применяются. В конфиге они сохранены для справки и проверки старых JSON fixtures. Получение из top само по себе не гарантирует нужного числа голосов. RSS также не даёт надёжных отдельных признаков закрепления и удаления.

Дубли объединяются по ссылкам Hugging Face/GitHub из текста и ссылок записи. Игнорируются параметры URL, якоря, ветки и пути файлов. У дублей RSS выбирается пост выше в своей top-ленте, при равной позиции — с более длинным текстом. Позиции двух разных объединённых лент не равнозначны рейтингу; это приближённый порядок. История опубликованных ссылок защищает от повторов после перезапуска. Разные релизы с одной ссылкой репозитория считаются одним релизом.

Каждая лента запрашивает до 100 записей (`rss_limit`), без пагинации. Поэтому активные сообщества могут вытеснять небольшие. При необходимости разбейте `rss_groups` на большее число групп или на отдельные сабреддиты. На выходных top/week с фильтром возраста даёт приближённую выборку 48 часов в пределах возвращённых записей.

## Сайты, лаборатории и рассылки

В `feeds` перечислены все дополнительные источники: TechCrunch AI, The Verge AI, Ars Technica AI, Wired AI, MIT Technology Review AI, The Register AI/ML, Tom’s Hardware AI, MarkTechPost, VentureBeat AI, The Decoder, SiliconANGLE AI; OpenAI, Google AI, DeepMind, Hugging Face, NVIDIA Developer, Qwen, Mistral; Simon Willison, Latent Space, Interconnects, Import AI; Hacker News. Anthropic читается из HTML страницы News, поскольку официальной RSS-ленты в задании нет.

Для каждого источника задаются `id`, `name`, `url`, `category`, `enabled`, `format` (`feed` или `html`) и `filter_mode` (`keywords` или `all`). Чтобы отключить сайт, установите `enabled: false`. TechCrunch добавлен один раз; файла `ai-shiz-sources.py` в этом проекте нет.

Если RSS содержит content:encoded, бот предпочитает этот текст короткому description. Парсер поддерживает RSS 2.0 с pubDate/content:encoded и Atom с published/updated, включая XHTML. Относительные ссылки приводятся к полным. Записи без даты пропускаются, чтобы не выдавать старую статью за новую. Даты без часового пояса считаются UTC; у Anthropic время публикации неизвестно, используется полночь UTC указанной даты. Список Anthropic читается без обхода всех статей и без пагинации; при изменении разметки адаптер сообщает об ошибке.

У сайтов применяются те же окна 24/48 часов. Проверки Reddit-флеров, рейтингов и тегов к ним не относятся. `site_include` проверяется по заголовку и первым 1500 символам текста и включает русские AI-термины. `site_exclude` отсеивает рекламу и розыгрыши. У профильных лент OpenAI/Google AI/DeepMind/Hugging Face/Qwen/Mistral/Anthropic включён `filter_mode: all`, остальные требуют AI-ключевые слова. URL Hacker News уже содержит фильтр LLM/GPT/Claude/Llama и points=150; отдельно рейтинг бот не получает.

Новости сайтов оформляются с названием издания и кнопкой-ссылкой «Читать статью». HN дополнительно показывает ссылку на обсуждение, если она есть в описании RSS. Дубли объединяются по URL статьи без UTM/якорей, одинаковому заголовку и общим Hugging Face/GitHub-ссылкам. В такой группе официальный блог лаборатории получает преимущество. Семантически одинаковые новости с разными заголовками и без общих ссылок могут остаться отдельными.

Проверка всех источников и обновление предпросмотра без повторного скачивания:

```sh
python3 scripts/check_feeds.py
python3 scripts/preview.py --snapshot data/feed-snapshot.json --limit 30
```

Проверка читает внешние сайты с тремя параллельными запросами, Reddit проверяет последовательно. Отчёт сохраняется в `data/feed-status.json`, снимок записей — в `data/feed-snapshot.json`. Это проверка доступности на момент запуска: 403/429, таймаут, пустая или устаревшая лента не означают, что источник будет постоянно работать. Бот при обычном запуске читает источники последовательно с заданной паузой.

## Текст статей TechCrunch

Для TechCrunch включено `fetch_article: true`: RSS находит публикацию, затем бот загружает страницу и извлекает абзацы из `entry-content` / `wp-block-post-content`. Меню, рекламные блоки, рассылки, подписи автора и рекомендации не включаются. Дополнительная загрузка выполняется только для свежих записей, прошедших фильтры.

В карточке и Telegram показывается начало статьи до 900 символов с обрезкой по границе предложения или слова, а не одна строка-анонс из RSS. Это исходный текст, а не автоматически написанное резюме. Если извлечение не удалось, сохраняется описание RSS; ошибка статьи не блокирует другие публикации. Кеш текста хранится в `data/articles` 6 часов. Паузы после ошибок сохраняются в общей базе кеша между перезапусками. Загрузка статей поддерживается только для домена TechCrunch; другие сайты по-прежнему используют содержимое RSS/Atom.

## Интервалы и ошибки

По умолчанию: проверка раз в 15 минут, 5 секунд между лентами, публикация не чаще раза в час, максимум 3 сообщения за проход. При часовом интервале фактически обычно отправляется одно. Кандидаты на следующем проходе переоцениваются и могут выбыть по возрасту.

Поддерживаются ETag и Last-Modified; кеш общий и сохраняется на диске. При HTTP 429 бот учитывает Retry-After (секунды или HTTP-дату) и сохраняет паузу не меньше 30 минут. Пока источник недоступен, использует допустимую по возрасту сохранённую копию или отмечает ошибку источника. Ошибка одной ленты не блокирует остальные. В логах указаны недоступные источники; дубли объединяются по доступной части выдачи. Ожидание действует для URL, а при 403/429/503 — для домена. Остальные домены продолжают работать. Доступность сайтов зависит от сети: RSS может возвращать 403/429 и не гарантирует постоянную работу без авторизации.

## Неопределённая отправка Telegram

Перед запросом записывается `pending`, после подтверждения — `sent` и ID сообщения. При таймауте или остановке процесса сообщение могло уже попасть в канал. Бот сохраняет `pending` и останавливает последующие отправки, чтобы не создать дубль. HTTP 429 и ошибки доступа Telegram тоже требуют проверки этой записи.

Остановите бот, проверьте канал и откройте базу (Python 3.12+):

```sh
python3 -m sqlite3 data/state.sqlite3
```

```sql
SELECT * FROM deliveries WHERE status = 'pending';
SELECT * FROM aliases WHERE delivery = 1;
```

Замените `1` на ID нужной записи. Если сообщение есть, подставьте его Telegram message ID вместо `123`:

```sql
UPDATE deliveries SET status = 'sent', message_id = 123 WHERE id = 1;
```

Если убедились, что сообщения нет, разрешите повтор:

```sql
BEGIN;
DELETE FROM aliases WHERE delivery = 1;
DELETE FROM deliveries WHERE id = 1 AND status = 'pending';
COMMIT;
```

После этого запустите бот. Не удаляйте базу при обычном обновлении: потеряется история дублей. Токены в базе не сохраняются, URL Telegram с токеном в лог не выводятся.

## Дашборд Signal и Top signals

Локальный дашборд использует те же источники и фильтры, но хранит накопленные записи отдельно от истории отправок Telegram.

```sh
python3 server.py --auto-refresh
```

Открыть `http://127.0.0.1:8765`. Сборщик работает без Telegram-токена. Кнопка «Обновить» запускает чтение источников в фоне и сохраняет прежнюю ленту, если обновление завершилось ошибкой. С `--auto-refresh` проверка повторяется раз в `poll_seconds`. Без этого флага обновление выполняется по кнопке. Для работы сервера нет необходимости запускать Telegram-публикатор.

Доступны канбан и список, поиск, периоды Trending Now / сутки / неделя / месяц / год, фильтры тем, выбор источника в каждой колонке, сохранение карточек и светлая тема. Сохранённые карточки и настройки вида хранятся в браузере. В сохранённом показываются записи выбранного периода. Архив в `data/news.sqlite3` накапливается при сборках; он не заменяет полную историческую выдачу источников. При первом запуске импортируются датированные записи имеющегося снимка, поэтому доступная глубина истории у разных сайтов различается.

Top signals — редакционная оценка, а не измерение достоверности. Максимум 100. Базовая схема (ниже — уточнения `editorial-v3`):

| Компонент | Максимум | Правило |
|---|---:|---|
| Тема | 30 | Приоритеты 1–5 дают 30/24/18/12/6 баллов |
| Свежесть | 25 | `25 × 2^(-возраст_в_часах / 24)` |
| Конкретика | 15 | Численные показатели +7, модель/репозиторий +5, исследование/benchmark +3 |
| Разные площадки | 15 | +7,5 за дополнительную площадку, максимум +15 |
| Первоисточник | 5 | В группе есть официальный блог лаборатории |
| Популярность | 10 | `min(10, 2.5 × log10(очки + 1))` по реально полученным очкам |

Отсутствующая популярность показана как «нет данных» и не добавляет баллов. HN-очки читаются из поля Points в описании RSS. Несколько сабреддитов считаются одной площадкой, Google AI и DeepMind тоже объединены. Появление на нескольких площадках не означает независимой проверки фактов: перепечатки тоже распространяют одну ссылку. Для карточек Top signals выбираются четыре истории с ограничением один источник на карточку, если данных достаточно. На карточке «Почему в топе» раскрывает вклад каждого компонента.

Скорость роста не рассчитывается: для неё нужны минимум два временных наблюдения одного и того же числового показателя. ИИ-резюме пока нет — карточки показывают выдержку из статьи/описания RSS. Если HN содержит только служебные поля, они не выдаются за описание статьи.

API:

- `/api/news` — JSON с архивными новостями, компонентами рейтинга и статусами источников.
- `/api/rss?sort=day` — объединённый RSS 2.0; также поддерживаются `now`, `week`, `month`, `year`, до 100 записей.
- `/api/status` — состояние фонового обновления.
- `POST /api/refresh` — запустить сбор без отправки в Telegram.

RSS содержит заголовок, короткое описание, исходную ссылку, стабильный GUID и дату. В пространстве имён `urn:ai-signal:feed:1` передаются источник, позиция, редакционный балл и количество площадок; сырые очки добавляются только при наличии. Рейтинг не копирует закрытый алгоритм референса.

### Объединение похожих статей

Одна новость из разных изданий, блогов, Reddit и HN показывается одной карточкой. Остальные материалы перечислены строкой «Также пишут» со ссылками и в разборе балла, охват считается по всем площадкам. Карточки моделей, репозиториев и статей HF не объединяются: `flux-klein` и `flux-klein-comfy` — разные артефакты, а новости о них учитываются в охвате.

Правило строже, чем сопоставление сюжетов для охвата, потому что объединённая карточка скрывает остальные:

- разница во времени до 48 часов;
- общий номер версии (v4.1, 5.5): не меньше половины значимых слов меньшего заголовка совпадают, и нет конфликта уточнений. «Nemotron 3.5 Super VL» и «Nemotron 3.5 Bolt» не объединяются: рядом с версией у каждого есть слово, которого нет в другом заголовке. Размеры (74b, a9b) уточнениями не считаются;
- без общей версии: не меньше 4 общих слов и похожесть Жаккара ≥ 0,4;
- два поста одной площадки — только при почти одинаковых заголовках (похожесть ≥ 0,7 и ≥ 4 общих слов);
- полная связность: статья входит в группу, только если похожа на каждую статью в ней, поэтому цепочка A≈B≈C не склеивает A и C.

Карточкой становится официальный источник, затем издание, затем самая ранняя публикация. Многотемный дайджест («Import AI 465: …; …», «[AINews] …») карточкой не становится. id карточки берётся от первой публикации, поэтому сохранённое не теряется, когда к сюжету добавляются статьи. В JSON и Markdown для агентов объединённые материалы передаются в поле `also`.

### Вкладки периода: Trending Now, Сутки, Неделя, Месяц, Год

Все вкладки отбирают записи по моменту, когда запись стала новостью (`news_at`): публикация статьи или поста, создание модели или статьи HF, первый день репозитория в GitHub Trending (у Trending нет даты создания репозитория). Для объединённого сюжета — первая публикация. Время последнего чтения трендов не учитывается: модель от августа, снова попавшая в тренды, не становится новостью дня.

| Вкладка | Окно | Порядок и число на карточке | Смысл |
|---|---|---|---|
| Trending Now (по умолчанию) | 12 часов | Импульс до 25 = популярность на платформе + охват площадок | что появилось за полдня и сильнее всего обсуждается |
| Сутки | 24 часа | Редакционный балл до 100 (со свежестью) | главное за день |
| Неделя / Месяц / Год | 7 / 30 / 365 дней | Значимость до 75 = редакционный балл без свежести | самое важное за период: внутри длинного окна новость не уступает более новой только из-за даты |

Число на карточке — показатель, по которому упорядочена вкладка; редакционный балл виден строкой «Ред. балл» и в разборе. Переключатель «Метрика источника» работает на всех вкладках, кроме Trending Now. В «Сутках» колонки GitHub/HF идут в порядке выдачи поставщика, на остальных вкладках — по показателю вкладки. Старые ссылки `?sort=now` открывают Trending Now.

Модель периодов задана в одном месте, `web/signal-ranking.js` (`PERIODS`), и повторена в `digest.py` (`WINDOWS`); общий набор тестовых данных проверяет, что страница и API отбирают и сортируют одинаково. RSS фильтрует период по тому же `news_at`.

### Чтение сайта агентами

Страница рендерится JavaScript-ом, но сервер сразу отдаёт в HTML готовую разметку: топ-4 сигнала и 40 записей ленты вкладки Trending Now (если сейчас пусто — за сутки), а также JSON-LD `ItemList` топ-10. Агент без браузера видит контент сразу. Заголовок `Link` и `<link rel="alternate">` указывают на машиночитаемые форматы. Все они строятся из той же публикации и в том же порядке, что и дашборд:

| Путь | Что отдаёт |
|---|---|
| `/llms.txt` | Описание сайта и эндпоинтов для LLM |
| `/signals.md` (или `/` с `Accept: text/markdown`) | Markdown-дайджест: общий топ и топ-5 каждой категории |
| `/api/signals` | Компактный JSON: даты в UTC ISO 8601, компоненты балла, отсутствующая метрика — `null` |
| `/robots.txt` | Разрешает обход и ссылается на `llms.txt` |

Параметры `/signals.md` и `/api/signals`: `sort` = trending/day/week/month/year — те же окна и порядок, что у вкладок; `now` (48 часов, редакционный балл) оставлен по умолчанию для совместимости API, `category` = all/models/repos/papers/media/enterprise, `limit` = 1..100 (по умолчанию 20). Неверные значения возвращают 400. Сборка также пишет `data/signals.md`.

Собрать автономный HTML и XML из сохранённого снимка:

```sh
python3 scripts/preview.py --snapshot data/feed-snapshot.json
```

Результат: `news-preview.html`, `data/dashboard.json` и `data/feed.xml`. Автономный HTML поддерживает поиск, фильтры и сохранение; обновление источников доступно через локальный сервер. В Docker дашборд обслуживает сервис `web`, сбор выполняет `worker`, адрес тот же: `http://127.0.0.1:8765`. Если порт занят уже запущенным локальным сервером, остановите его перед запуском Docker-сервиса.

## GitHub Trending, Hugging Face Models и Papers

Подключены три адаптера без API-ключей:

| Источник | Данные | Доступ |
|---|---|---|
| GitHub Trending | Репозиторий, описание, язык, звёзды за день, всего звёзд, форки | HTML `https://github.com/trending?since=daily` |
| Hugging Face Models | Модели в порядке trendingScore, задача, библиотека, лицензия, лайки и скачивания | `/api/models?sort=trendingScore&limit=30&full=true&cardData=true` |
| Hugging Face Papers | Название, авторская аннотация, голоса, комментарии, arXiv и GitHub | `/api/daily_papers?sort=trending&limit=30` |

В канбане это отдельные колонки. Внутри них сохраняется порядок поставщика (после наших фильтров и объединения дублей), а блок Top signals использует редакционный балл. GitHub проходит AI-фильтр по заголовку и описанию. Модели и Papers принимаются без дополнительного фильтра ключевых слов. Блог Hugging Face остаётся в колонке лабораторий и авторов.

Попадание в тренды не означает создание нового репозитория/модели или выход новой статьи. В карточке показано «В трендах» и время наблюдения. Исходная дата создания модели или публикации статьи передаётся отдельно; у GitHub Trending дата создания репозитория неизвестна и не выдумывается. Для временных фильтров и свежести рейтинга используется момент наблюдения в Trending. Если запись исчезает из выдачи, архив хранит время последнего наблюдения. При HTTP 304 список подтверждён источником повторно, время наблюдения обновляется. При обычном попадании в кеш время наблюдения не меняется.

Метрики отображаются с единицами: звёзды за сутки и всего звёзд, лайки, скачивания за месяц, голоса. Нулевое число сохраняется как 0, отсутствующее не подменяется нулём. Модели показывают метаданные API/model card без обхода README каждой модели. Papers используют оригинальный abstract; поле `ai_summary` не выдаётся за авторский текст.

Текущая версия рейтинга — `editorial-v3`. Шесть компонентов и их максимумы прежние, но каждый считается из данных, которые есть у конкретного типа записи:

- **Тема.** Приоритеты по тексту, как у Telegram-бота. Дополнительно заголовок новости или блога, где названо отслеживаемое семейство (`models` в конфиге) и есть глагол релиза (released, launches, introducing…), считается релизом модели (30). Модель из трендов HF получает 30, если в её id есть отслеживаемое семейство, иначе 24. Репозиторий получает 18 только при AI-ключевых словах (agent, MCP, inference…), иначе 6. Papers — 12.
- **Свежесть.** `25 × 2^(-возраст / полураспад)`. Возраст считается от реальной даты, а не от момента обращения к трендам: для Papers — дата публикации статьи (полураспад 72 ч), для моделей — `createdAt` (168 ч), для GitHub Trending — первое появление в архиве (24 ч), для новостей — публикация (24 ч). Старая статья или модель, снова попавшая в тренды, свежей не считается.
- **Популярность.** `min(10, 10 × ln(value + 1) / ln(target + 1))`. GitHub — звёзды за сутки, target=1000 (weekly/monthly — 7000/30000). Модели — `trendingScore` Hugging Face (скорость лайков), target=1000. Лайки за всё время (target=1000) — только запасной вариант. Papers — голоса, target=300. HN/Reddit — `min(10, 2.5 × log10(points + 1))`. У журналов и блогов метрики нет: компонент показан как «нет данных».
- **Разные площадки.** Учитываются площадки в группе дублей и площадки с тем же сюжетом в пределах 72 ч. Эти записи не склеиваются. Сюжет совпадает, если у заголовков общие два токена версии (`v4.1`, `qwen3.8`), один токен версии плюс общее слово, или не меньше трёх общих основ слов при Жаккаре ≥ 0,4. Голые числа и размеры (`100`, `27b`, `1m`) не считаются версиями. Так заметка журнала о релизе получает охват от самой модели на HF, Reddit и других изданий. В разборе балла перечислены эти площадки.

Это редакционные пороги насыщения, а не статистические процентили. В группе дублей берётся максимальный нормированный компонент, а не сумма разных единиц. Баллы разных платформ нужны для редакционной очереди и не означают одинаковый реальный охват. На карточке раскрываются использованная метрика и её порог.

Обновить только эти три источника, не перечитывая все остальные:

```sh
python3 scripts/update_trends.py
```

Обычная кнопка «Обновить» и автообновление сервера также собирают все три источника. В RSS передаются тип даты, исходная дата публикации и отдельные элементы `signal:metric` с видом метрики и единицами.

Документация: [GitHub Trending](https://github.com/trending), [Hugging Face Hub API](https://huggingface.co/docs/hub/api), [сортировка моделей](https://huggingface.co/docs/huggingface_hub/main/en/package_reference/hf_api), [Hugging Face Papers](https://huggingface.co/papers/trending).

## Общий дисковый кеш и ограничения запросов

Все загрузки источников проходят через `http_cache.py`. База `data/http-cache.sqlite3` и каталог блокировок `data/http-cache.sqlite3.locks` общие для дашборда, Telegram-сборщика, проверки источников и скрипта трендов. Они сохраняются в Docker благодаря тому же тому `data`. Другой путь задаётся `HTTP_CACHE_DB`.

Загрузка HTML дашборда, `/api/news`, `/api/rss` и переключение фильтров не обращаются к внешним сайтам. Сбор запускается кнопкой или таймером, а сборщик сначала проверяет TTL. Кнопка защищена от повторного запуска того же задания и имеет паузу 60 секунд между запусками; принудительного обхода кеша в интерфейсе нет.

| Данные | TTL по умолчанию |
|---|---|
| RSS/Atom, включая Reddit | 15 минут |
| HTML страницы источника | 30 минут |
| GitHub Trending | 30 минут |
| Hugging Face Models | 30 минут |
| Hugging Face Papers | 60 минут |
| Текст статьи TechCrunch | 6 часов |

Настройки находятся в `config.json` → `cache`. У отдельного источника можно задать положительное `cache_ttl_seconds`. Уменьшение TTL учитывается и для уже сохранённых ответов.

После истечения TTL отправляется условный запрос с сохранёнными `If-None-Match` / `If-Modified-Since`, если источник их поддерживает. Ответ 304 продлевает кеш без скачивания тела. Новый ответ проверяется парсером до замены старого: HTML-заглушка вместо RSS или неправильный JSON не портят последнюю успешную копию.

При 429 учитывается `Retry-After` в секундах или формате HTTP-даты; пауза не меньше 30 минут и сохраняется в SQLite. Паузы при 403/429/503 распространяются на домен; обычные ошибки — на конкретный URL. После других ошибок повтор для URL разрешается не раньше чем через 15 минут. Свежий кеш можно читать даже во время паузы домена. У источников на одном домене сетевые запросы идут последовательно, с интервалом минимум 2 секунды после окончания предыдущего запроса. Разные процессы используют одинаковые файловые блокировки, поэтому один и тот же URL одновременно скачивается только один раз.

Если источник временно недоступен, разрешено показать последнюю успешную копию в течение суток после окончания её TTL (`stale_if_error_seconds`). В статусах это `stale`, в интерфейсе — «Сохранённые данные · источник недоступен». Такая копия не получает новую дату наблюдения или публикации. Если копия слишком старая или её нет, источник помечается недоступным. Остальные источники продолжают работу.

В `/api/news` → `statuses` видны поля `cache` (`hit`, `miss`, `revalidated`, `stale`), `checked_at` и `expires_at`. Эти времена относятся к источнику; время сборки дашборда не заменяет дату его последней сетевой проверки. Parsed-кеш текстов TechCrunch в `data/articles` сохранён дополнительно, чтобы не разбирать HTML статьи заново при каждом проходе. Запрос отправки Telegram через GET-кеш не проходит.
